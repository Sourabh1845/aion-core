Sample Project: Support Agent With Browser + CRM + Email

52/100Risk score

Launch Blockers

Outbound email can run without approval.

The agent can read customer data and send email. That creates accidental disclosure and prompt-injection risk.

Browser + CRM write actions are not scoped.

The workflow does not define allowed domains, allowed CRM fields, or denied actions.

No evidence trail for tool calls.

There is no clear allow/block/approval receipt for customer-impacting actions.

Fix Plan

1. Add approval gates.
  • Require approval before sending email, editing CRM records, or escalating tickets.
  • Auto-allow read-only ticket lookup and non-sensitive summaries.
  • Auto-block requests that include secrets, full payment data, or private credentials.
2. Scope tool permissions.
  • Browser: allow only support docs and status pages.
  • CRM: allow customer lookup and note draft, deny delete/export/admin changes.
  • Email: draft-only until a human approves send.
3. Add launch evidence.
  • Record a receipt for each tool decision with allow, block, or approval_required.
  • Store project, actor, tool, reason, severity, and timestamp.
  • Export a launch report for the pilot customer or internal reviewer.

Final Verdict

Do not launch with autonomous outbound email and broad CRM writes. Ship a pilot only after approval gates, scoped tool permissions, and evidence logging are added.
